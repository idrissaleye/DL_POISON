Attaque par empoisonnement des données

Cette fois on corrompt les données d'entraînement puis on ré-entraîne : c'est le modèle lui-même qui devient vulnérable.
• Retournement d'étiquettes : une fraction des labels est modifiée.
• Porte dérobée (backdoor) : un motif déclencheur est collé sur des images relabelées vers la classe cible ; à l'inférence, toute image portant le motif est classée « cible ».

🛡️ Défense 1 — Prétraitements d'entrée (contre l'évasion)

Sans ré-entraînement : on « nettoie » les entrées (quantification, flou, médian, JPEG) pour détruire la perturbation. Mesure : précision sous attaque avec et sans défense.

Zoom : propre → adversarial → prétraité

🛡️ Défense 2 — Entraînement adversarial (contre l'évasion)

Ré-entraîne un modèle en injectant des exemples adversariaux dans chaque batch (Madry et al. 2018). Le modèle apprend à rester correct sur les données perturbées.

🛡️ Défense 3 — Détection & filtrage des données empoisonnées

Un modèle entraîné sur des données empoisonnées attribue une perte anormale aux exemples corrompus. On détecte les outliers (seuil statistique z), on les retire, puis on ré-entraîne sur les données nettoyées. Fonctionne après une attaque de l'onglet 4.
